## 1. 目的与范围

- **业务目标引用**：`BRD-OBJ-TBD`（尚无正式 BRD；对齐总目标：运营人员可在 Web 管理端安全登录并治理 AdminUser）
- **问题陈述**：后端 Admin Identity API 已就绪，但管理端前端仍为占位空壳，无法完成登录与账号治理的可操作闭环；若前端自行发明身份概念或弱化能力矩阵，将与后端契约漂移。
- **假设**：
  - 后端 V0.1 API 可用（含 Bootstrap Admin：`admin` / `admin@123456`）。
  - 领域实体与能力矩阵以后端 `CONTEXT.md` 为准；本 PRD 只定义 **UI 行为与验收**。
  - 视觉由后续 Pencil 设计后再换皮；本阶段样式以可替换为前提。
- **范围内**：
  - 登录页（含记住用户名）、登出、会话恢复与过期跳转
  - 管理壳层（侧栏：首页 / 账号管理；顶栏：身份、改密、登出）
  - 首页空占位
  - 账号列表（分页、username 模糊、role 筛选）
  - 创建 / 重置他人密码 / 变更角色 / 删除（模态框；Staff 灰显）
  - 修改自己的密码（顶栏入口；成功后强制重新登录）
  - 字段校验、业务错误与 Toast 反馈策略
- **范围外**：
  - 视觉定稿 / 设计系统落地（Pencil 后续）
  - 启用 / 停用、自定义角色、验证码、失败锁定
  - 昵称 / 头像 / 邮箱、审计日志页
  - 强制首次登录改密
  - EndUser 相关页面、RAG 业务页面
  - 后端 API 变更（本 PRD 只消费已有契约）

## 2. 目标与护栏

- **首要指标**：使用 Bootstrap Admin 可在管理端完成「登录 → 首页 → 账号列表 → 创建 Staff → 重置/改角色/删除（非保护对象）→ 登出」闭环；Staff 登录后可见列表且写操作不可用（灰显）。
- **次要指标**：
  - 刷新页面后有效会话可恢复；无效 / 作废 token 进入登录页
  - Staff 写操作入口布局与 Admin 一致（灰显，非隐藏）
  - 任何 UI 不展示密码或哈希
- **护栏**：
  - 不绕过后端鉴权（前端灰显是体验，不是安全边界）
  - 不引入 Operator / User 等与词汇表冲突的实体名
  - Token 仅存 localStorage；不缓存密码；记住用户名仅缓存 username

## 6. 功能行为说明（FRS 精简）

### 6.1 主流程

1. **首次使用**：打开管理端 → 登录页 → `admin` / `admin@123456`（或已改密后的凭证）→ 首页占位。
2. **账号治理（Admin）**：侧栏进账号管理 → 创建 / 筛选 → 行内重置、改角色、删除。
3. **Staff 日常**：登录 → 查看列表（写操作灰显）→ 顶栏改自己密码或登出。
4. **会话恢复**：刷新 → `me` 成功继续；失败或业务未登录码 → 回登录页。

### 6.2 异常 / 分支流程

- 登录失败 → 页内错误条。
- 表单校验失败 → 字段内联。
- 业务失败（无权限、保护规则、冲突）→ 弹窗或页内展示 `message`。
- 网络 / 未知错误 → Toast。
- 改己密成功 → 强制重新登录（可预填已记住的用户名）。

### 6.3 屏态与导航

| 屏 | 路由意图（逻辑） | 说明 |
| --- | --- | --- |
| 登录 | `/login`（或等价） | 匿名；已登录则重定向首页 |
| 首页占位 | `/` 或 `/home` | 需登录 |
| 账号列表 | `/users` 或 `/admin-users` | 需登录；文案用「账号管理」 |
| 写操作 | 无独立路由 | 模态框 |

### 6.4 能力矩阵（UI 层，与后端一致）

| 动作 | Admin | Staff |
| --- | --- | --- |
| 登录 / 登出 / 改己密 / 列表 | 能 | 能 |
| 创建 / 重置他人密码 / 改角色 / 删除 | 能（受保护规则） | **入口灰显，不能提交** |

### 6.5 输入边界（与后端对齐）

- **用户名**：4–32；`[a-zA-Z0-9_]`；创建后不可改。
- **密码**：8–64；须含字母与数字；响应永不展示。
- **角色**：`ADMIN` / `STAFF`（展示可用中文「管理员」「运营人员」，值与 API 枚举一致）。
- **列表**：默认 pageSize=20，上限 100。

## 7. 非功能产品约束

- **性能**：常规内网下登录与列表可手工验收；不设严格 P95。
- **安全 / 隐私**：
  - Token 仅 localStorage（ADR-0002）；不存密码
  - 前端灰显不等于授权；一切写操作以后端为准
  - 不在 UI/日志中输出 token 明文到可分享界面
- **无障碍 / 可用性**：本阶段不设 WCAG 硬指标；禁用控件须有可感知原因（tooltip 或等价）。
- **平台**：桌面浏览器优先（Chrome / Safari / Edge 近两个大版本）；不承诺移动端管理体验。
- **视觉**：不定稿；实现保持结构清晰、可换皮。
