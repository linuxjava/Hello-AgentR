## 1. 目的与范围

- **业务目标引用**：`BRD-OBJ-TBD`
- **问题陈述**：V0.2 管理端按 `string[]` 消费模型目录；V0.3 后端目录已升级为对象列表（`id/model/dimension/providerId/priority/isDefault`）。若前端不对齐，会导致创建弹窗无可选项或错误映射，阻断建库闭环。
- **假设**：
  - 后端 V0.3 已上线并返回对象目录；创建知识库时由后端自动绑定默认模型（前端不传 `embeddingModel`）。
  - 管理端仍沿用 V0.2 页面形态（列表 + 创建/编辑/删除模态）。
  - 本版本不引入新视觉系统重构，仅做契约与行为对齐。
- **范围内**：
  - 适配 `GET /admin/embedding-models` 新响应结构
  - 创建弹窗模型下拉、提交、错误态与禁用态对齐
  - 列表“向量模型”列值展示规则对齐
  - 既有 Admin/Staff 权限与删除行为回归验证
- **范围外**：
  - 后端 API 变更
  - Chat/LLM 配置相关 UI
  - 新增 Provider 管理页
  - 账号治理模块改造
  - 全量视觉换皮

## 2. 目标与护栏

- **首要指标**：Admin/Staff 能完成「进入知识库 → 打开创建 → 拉取对象目录 → 选择模型并创建成功 → 列表展示正确模型 id」闭环。
- **次要指标**：
  - 目录失败时创建不可提交，错误反馈清晰
  - Staff 删除行为与 V0.2 保持一致（不可提交删除）
- **护栏**：
  - 创建请求字段仍是 `embeddingModel`（值为目录项 `id`），不得改协议
  - 不在 UI 端拼接/推导 provider 敏感信息
  - 不展示后端未返回的虚构字段
  - 不改变 `Namespace`、`EmbeddingModel` 创建后不可修改规则

## 6. 功能行为说明（FRS 精简）

### 6.1 目录消费规则

- 请求：`GET /admin/embedding-models`
- 响应字段：`id`、`model`、`dimension`、`providerId`、`priority`、`isDefault`
- 前端最小消费要求：
  - 必用：`id`
  - 可用展示增强：`model`（如有产品要求）
  - 当前版本不展示 `providerId` / `dimension`，但允许保留在前端类型中

### 6.2 创建弹窗行为

- 不提供模型选择控件（不可选）
- 可展示只读提示：“由后台默认模型决定”
- 提交参数不包含 `embeddingModel`
- 即使目录查询失败也不阻断创建（由后端统一决策默认模型）

### 6.3 列表展示行为

- 列“向量模型”继续展示 `embeddingModel`（id）
- 不因目录对象新增字段而变更知识库列表数据源
- 不新增 Provider 列（本期）

### 6.4 权限与错误处理

- 登录/会话逻辑沿用 V0.1
- Staff 删除仍由 UI 限制 + 后端兜底
- 业务错误文案沿用后端 `message`

## 7. 非功能产品约束

- **兼容性**：仅消费后端 V0.3 契约；对旧 `string[]` 不做双轨兼容
- **可维护性**：前端模型类型与后端响应字段一一对应，避免“any”穿透
- **安全**：界面不展示密钥或连接配置，不缓存敏感字段
