## 1. 目的与范围

- **业务目标引用**：`BRD-OBJ-TBD`（尚无正式 BRD；对齐总目标：运营可在 Web 管理端把本地文件纳入已有 KnowledgeBase，并锁定后续如何切块，但不在本版本切块）
- **问题陈述**：后端 V0.4 已提供 Document 上传与元数据治理，管理端仍停在 V0.2/V0.3 的容器列表（且曾把「文档数」当假字段禁止展示）。运营无法进入某库、传文件、改策略或删错传；删库的「有文档则不能删」也无法在界面上被真实数据驱动。
- **假设**：
  - 后端 V0.4 API 可用（`/admin/knowledge-bases/{id}/documents/**`；列表/详情含 `documentCount`）；会话与角色沿用 V0.1，知识库容器行为沿用 V0.2/V0.3。
  - 领域实体与能力矩阵以后端 Knowledge / Admin Identity 词汇表为准；本 PRD 只定义 **UI 行为与验收**。
  - 本阶段**不**执行切块、**不**提供源文件预览/下载；界面**不**为此写免责横幅（grilling Q13 = C）。
  - 交互模式沿用既有壳层：库级写操作仍在知识库列表模态；Document 写操作在文档列表模态；Enabled 为行内开关。
  - 视觉由后续 Pencil 再换皮；本阶段样式以可替换为前提。
- **范围内**：
  - 知识库列表增加文档数；**点击名称**进入文档列表（名称前有图标）
  - `documentCount > 0` 时 Admin 点删除以 Toast 拦截（外观不灰显）
  - 独立文档列表（不是知识库详情页）：文件名搜索、分页、状态列、启用开关
  - 单文件上传（结构化策略表单 + 预填）
  - 改 ChunkStrategy、启用/禁用、删除 Document
- **范围外**：
  - 开始分块、解析、切片数、索引状态、Chunk 实体 UI
  - 源文件预览 / 下载；URL 地址上传；多文件一次提交
  - JSON 文本框编辑策略参数；覆盖已有同名文件
  - 知识库详情页（上半改库、下半文档）
  - 按 status / strategy / enabled 筛选文档
  - 账号启用/停用、账号治理行为变更
  - 后端 API / ObjectStorage 配置变更
  - 视觉定稿 / 设计系统落地（Pencil 后续）

## 2. 目标与护栏

- **首要指标**：Admin 或 Staff 可完成「知识库列表看见文档数 → 进入某库 → 上传一份合法文件并带策略 → 列表可见（含状态）→ 改策略 → 开关禁用再启用 → 删除文档 → 文档数归零后 Admin 可删该空库」闭环。
- **次要指标**：
  - Staff 可删除 Document，但删知识库仍灰显（无权限）
  - 有文档时 Admin 删库不可打开确认框
  - 非法文件 / 策略参数 / 存储失败：弹窗内后端 `message`，列表无脏数据
- **护栏**：
  - 不绕过后端鉴权与 Tika 权威
  - 不引入 Dataset、Collection、知识库详情、附件等与词汇表冲突的名称
  - 不展示 objectKey、存储密钥、切片数、索引状态
  - 不把扩展名当安全边界；不把 UI 预填参数写成领域常量
  - Token / 会话行为不回退 V0.1

## 6. 功能行为说明（FRS 精简）

### 6.1 主流程

1. **选库**：已登录 → 侧栏「知识库管理」→ 知识库列表（含文档数）→ **点击名称**进入文档列表。
2. **上传**：文档列表页头「上传」→ 拖拽或点击选一份本地文件 → 确认或修改策略数字 → 提交（锁定中）→ 成功 Toast → 列表刷新。
3. **查找**：OriginalFilename 模糊 + 分页；已禁用仍列出。
4. **改策略**：行内「改策略」→ 回填 → 可改文件名主名（后缀锁定）→ 可换种类（字段整份替换）→ 提交。
5. **启用/禁用**：行内开关，点即提交。
6. **删文档**：轻确认 → 删除 → 文档数降为 0 后 Admin 可在知识库列表删库。

### 6.2 异常 / 分支流程

- 未登录 / `A000001` → 清会话回登录页（V0.1）。
- 知识库不存在（`A002001`）→ 不能停留在可上传的空文档页。
- 文档不存在或不属于该库（`A002009`）→ 弹窗或 Toast 展示 `message`，列表刷新。
- 策略数字不合规 → 内联错误，不关闭弹窗。
- 业务失败（空文件、类型、超限、策略、存储）→ 弹窗内 `message`。
- 网络 / 未知错误 → Toast。
- 有文档时 Admin 点删库 → Toast「库下仍有文档，不能删除」，不打开确认；删除不用禁用色。若仍收到 `A002008`（列表未刷新），确认框内展示文案。

### 6.3 屏态与导航

| 屏 | 路由意图（逻辑） | 说明 |
| --- | --- | --- |
| 知识库列表 | 沿用 V0.2（如 `/knowledge-bases`） | 新增文档数列；点名称进入 |
| 文档列表 | `/knowledge-bases/{id}/documents`（或等价；实现前工程选定） | 需登录；侧栏仍「知识库管理」 |
| 上传 / 改策略 / 删除文档 | 无独立路由 | 挂在文档列表页的模态框 |
| 知识库详情 | **不存在** | 禁止做成上半改库、下半文档 |

侧栏三项不变：**首页** | **账号管理** | **知识库管理**。顶栏身份区不改。

| 动作 | Admin | Staff |
| --- | --- | --- |
| 知识库列表（含文档数）/ 进入文档列表 | 能 | 能 |

### 6.5 输入边界（与后端对齐；UI 预填不是领域常量）

- **上传**：`multipart` 单文件；`chunkStrategy` + 前端组装的 `chunkStrategyParams` JSON 字符串。
- **选文件**：支持拖拽到投放区或点击选择；`accept` 提示 txt/md/pdf/doc/docx/ppt/pptx/xls/xlsx/png/jpg/jpeg/svg；投放区只提示类型，不写约 50MB / 服务端为准。权威为 Tika 与部署配置。已选后可拖拽替换或点击重选。
- **上传预填**：默认 `OVERLAPPING`，`chunkSize=512`，`overlap=64`；切到 `STRUCTURE_AWARE` 为 `minChunkSize=256`、`defaultChunkSize=512`、`maxChunkSize=1024`、`overlap=32`。字段旁不标注单位。
- **策略下拉文案**：`OVERLAPPING` →「重叠分块」；`STRUCTURE_AWARE` →「文档结构分块(建议MD文档使用)」。
- **策略字段控件**：输入盒内侧左侧装饰图标（与 Pencil 一致）；数字直接键入无前导 `0`、无原生步进器；下拉无水波纹 / 波浪；玻璃输入盒焦点高亮对齐 Ant Design outlined Input。
- **改策略**：打开时回填已存值；文件名主名可改、后缀只读；改种类则目标种类默认预填（与上传切种类相同），提交为整份 JSON 替换，并带完整 OriginalFilename。
- **不等式（内联）**：`OVERLAPPING`：`chunkSize > 0` 且 `0 ≤ overlap < chunkSize`。`STRUCTURE_AWARE`：三者 `> 0` 且 `minChunkSize ≤ defaultChunkSize ≤ maxChunkSize` 且 `0 ≤ overlap < minChunkSize`。
- **文档列表**：默认 pageSize=20，上限 100；OriginalFilename 模糊；可选 `status` / `enabled` 精确筛选（点「查询」生效，缺省不过滤）；不做 strategy 筛选；默认更新时间倒序。禁用文档在未筛启用时仍列出。
- **列表列**：文件名（OriginalFilename）、状态、分块数、Enabled、updatedAt、操作（改策略 / 删除）。文件名下方副行展示文档类型与大小（`mediaType` → 可读标签如 PDF/Markdown/Word；`byteSize` → 人类可读），格式 `类型 · 大小`，不另开列。`UPLOADED` 在界面展示为「待分块」；尚未分块时分块数展示「—」。状态为**色点 + 文字、无底色**：待分块灰 / 分块中蓝 / 分块成功绿 / 分块失败红。
- **不展示**：策略摘要、objectKey、sourceType、createdBy（本版本不要求）；类型与大小仅作文件名副行，不设独立列。
- **删除文档文案**：轻确认，例如「确定删除该文档？」；不写对象存储 / 不可下载。

### 6.6 反馈（沿用 V0.1 / V0.2）

- 字段校验：表单内联。
- 业务失败：弹窗内 `message`（开关失败可用 Toast 展示 `message`）。
- 业务成功（上传 / 改策略 / 开关 / 删除）：Toast；弹窗则关闭并刷新列表。
- 全局意外：Toast。
- 界面**不**提示「本版本不切块 / 不可预览下载」。

## 7. 非功能产品约束

- **性能**：常规内网下上传与列表可手工验收；不要求分片/断点续传；不设严格 P95。
- **安全 / 隐私**：
  - 复用 V0.1 会话（ADR-0002）；不另存密码
  - 不展示 objectKey / 存储密钥；灰显不等于授权
  - 不以客户端 MIME / 扩展名为准
- **无障碍 / 可用性**：本阶段不设 WCAG 硬指标；两处删库禁用须能区分「无权限」与「有文档」。
- **平台**：桌面浏览器优先（Chrome / Safari / Edge 近两个大版本）；不承诺移动端管理体验。
- **视觉**：不定稿；结构清晰、可换皮。
